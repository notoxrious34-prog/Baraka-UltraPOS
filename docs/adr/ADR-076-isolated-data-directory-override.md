Title: ADR-076 Isolated data directory override (BARAKA_DATA_DIR)
Status: Accepted
Context: The application stores its database and related files under a fixed per-user location holding the owner's real shop data. Runtime evidence (screens, timing, window measurements) of the real application cannot be collected without risking that data.
Decision: An opt-in environment variable BARAKA_DATA_DIR redirects the data directory. Unset or empty means the default behavior, unchanged. When set it must be an absolute path without ".." components and must not be, or lie inside, the default data directory (lexical check, then a canonical check after creation). An invalid value aborts startup with a diagnostic; the default directory is never used as a fallback. In override mode the main window title carries the marker [BARAKA_DATA_DIR] and the webview profile folder is redirected inside the override directory. This is a developer and test facility with no user interface and no end-user documentation.
Consequences: Later audit and design tasks can run the real built application against scratch copies. Junction or symlink tricks inside an override path are not defended beyond the canonical check. The facility never replaces the rule that tests use copies, not the live database.
