# ADR-123 — مزامنة صندوقين دون تصادم تسلسل (S5 / BRK-124 لاحقًا)
**الحالة:** PROPOSED. **التاريخ:** 2026-11-15.
**السياق:** القاعدة ملف SQLite واحد لكل آلة (أوفلاين مطلق). صندوقان =
ملفا قاعدة مستقلان. `document_sequences(type, fiscal_year)` سراسري، فالدمج
الساذج يصادم الأرقام البشرية (`TICK-2026-000001` مكررًا) ويكسر دفتر الأستاذ.

## القرار
1. الهوية سراسرية أصلًا: كل الصفوف بمفاتيح UUID + `command_log`
   (مفاتيح عدم التكرار) + `origin_device_id` على كل مستند — الدمج
   **بالمفاتيح لا بالأرقام**، والاستيراد idempotent (إعادة نفس الحزمة = صفر أثر).
2. عند الاستيراد تُعاد ترقيم مستندات الطرفية المستوردة من تسلسل
   المستورِد، مع حفظ الرقم الأصلي في عمود جديد `origin_number`
   (ترحيل إلحاقي 0024+) — دفتر الأستاذ والتدقيق يُعاد اشتقاقهما محليًا.
3. صندوق صادر `sync_outbox` إلحاقي (0024+): كل كتابة ملتزمة تُذيَّل
   `(entity, entity_id, at)`؛ التصدير = حزمة JSONL منذ المؤشر + تجزئة
   تدقيق للتحقق. لا حذف، لا تحديث — الدمج أحادي الاتجاه لكل حزمة.
4. التعارض الوحيد الحقيقي (رصيد مخزون سالب بعد الدمج) يُحل بسياسة
   معلنة: المستورِد يفوز رقميًا + تنبيه `stock.noRupture`-مضاد في الرادار،
   لا دمج صامت.

## البدائل المرفوضة
- كتل مرقمة مسبقة لكل صندوق (هشة عند الثالث؛ نفاد الكتلة = توقف بيع).
- خادم تسلسل مركزي (يكسر «أوفلاين مطلق» — مرفوض دستوريًا).
- الاحتفاظ برقمي الطرفيتين (رقمان لنفس المستند = كسر التدقيق والطباعة).

## القبول (للتنفيذ لاحقًا)
- قاعدتا scratch تندمجان: صفر تصادم أرقام + `origin_number` محفوظ +
  معادلة الائتمان والمجاميع مطابقة قبل/بعد + إعادة نفس الحزمة صفر أثر.

## 💡 ابتكارات وأفكار تطويرية مقترحة
1. **حزمة QR للطوارئ:** تصدير دفعات صغيرة (نهاية اليوم) كـ QR
   مشفر يُمسح من الطرفية الثانية بلا شبكة — قيمة: مزامنة السوق الأسبوعي.
2. **ميزان الدمج البصري:** شاشة قبل/بعد (مجاميع + متنازع عليها) بزر
   «اعتماد» واحد — قيمة: ثقة المدير بلا SQL.
