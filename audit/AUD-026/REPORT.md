## 8. Defects Resolved & Deferred

### 8.1 RESOLVED — shaping scale `/64.0` (pre-existing engine bug, fixed with failure-first test)

`shape_run` (`crates/infrastructure/src/printing/shaping.rs`) computed
`scale = px_size / upem / 64.0`. rustybuzz 0.18 returns advances in FONT UNITS,
not 26.6 fixed point — measured raw values on a 1000-upem Noto face:
`x_advance` 636/253/360/387/456 for a 5-glyph Arabic word, `1443` for Latin
`A` in a 2048-upem Inter face (both ≈ 0.6em, i.e. font units). The extra `/64.0`
compressed every line ~64×: a 63-char Latin designation at 24px measured
**11.53px**, a 100-char Arabic designation **15.69px**, so text rendered as an
ink blob at the margin and `layout_lines` winding could never trigger
(4×400 Arabic chars still produced 58mm == 80mm = 428 rows).

Resolution per the Regression Law — the guard was written and shown to FAIL on
the defective code before the fix:
`shaping_advances_are_physical_pixels` → `latin: 0.183 px/char at 24px is not a
physical advance (width=11.53px for 63 chars)`; `long_designation_wraps_on_both_canvases`
→ `58mm must wrap (550) above 80mm (550)`. Fix: `let scale = px_size / upem;`.
After the fix both guards and the width/stride tests are green, and 58mm
genuinely wraps above 80mm. No byte-exact print goldens existed; all print
suites (`print_rendering`, `debt_receipt_rendering`, `print_worker`,
`store_identity_tests`) pass unchanged.
