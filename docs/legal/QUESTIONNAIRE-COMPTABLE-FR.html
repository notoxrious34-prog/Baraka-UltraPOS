Annexe A — Règle de droit de timbre actuellement programmée (non validée)

La fonction compute_timbre (crates/domain/src/sales/pricing.rs:156-169) reçoit le type de document, le montant réglé en espèces et la base de calcul. Elle ne s'applique qu'aux documents de type Ticket ou Facture, et uniquement lorsque le montant réglé en espèces est strictement supérieur à zéro ; dans tous les autres cas elle retourne 0. Le montant en espèces pris en compte est la somme des parts de paiement dont la méthode est Cash (espèces) ; seule cette méthode est considérée comme espèces (crates/domain/src/sales/payment.rs:10-19 pour les quatre méthodes Cash, Credit, Cheque, Card ; crates/domain/src/sales/payment.rs:48-50 pour la règle). La base de calcul est le sous-total HT augmenté de la TVA totale (crates/domain/src/sales/pricing.rs:334-337) ; dans le parcours d'encaissement actuel le taux de TVA appliqué vaut 0 (crates/application/src/use_cases/sales.rs:103), la base égale donc le sous-total. Le calcul se fait en nombres entiers : ((base + 9 999) / 10 000) × 100 (crates/domain/src/sales/pricing.rs:167), soit 1 % de la base arrondi au multiple supérieur de 100 centimes (1 DA). Le résultat est borné : minimum 500 centimes, soit 5 DA (TIMBRE_MIN_CENTIMES, crates/domain/src/sales/pricing.rs:148) ; maximum 250 000 centimes, soit 2 500 DA (TIMBRE_MAX_CENTIMES, crates/domain/src/sales/pricing.rs:150). Le timbre calculé est ajouté au total du document (crates/domain/src/sales/pricing.rs:338-341). Le calcul exclut tout timbre de sa propre base (non circulaire). Le calcul est effectué au moment du chiffrage du document (price_document, appelé depuis crates/application/src/use_cases/sales.rs:115) à partir des paiements qui accompagnent la vente. Comportement lors d'un versement ultérieur en espèces pour une vente à crédit : Non déterminé. Prise en charge par le client ou par le vendeur : Non déterminé. Présentation sur le document (ligne séparée ou incluse dans le total) : Non déterminé à partir du seul moteur de calcul (le modèle d'impression prévoit un champ timbre : crates/domain/src/printing/receipt_model.rs:54).

Cette règle est celle actuellement programmée ; elle n'a pas été validée par un professionnel.

pub const TIMBRE_MIN_CENTIMES: i64 = 500;
pub const TIMBRE_MAX_CENTIMES: i64 = 250_000;

pub fn compute_timbre(
    doc_type: DocumentType,
    cash_tendered_centimes: i64,
    base_for_timbre_centimes: i64,
) -> i64 {
    let applicable = matches!(doc_type, DocumentType::Ticket | DocumentType::Facture)
        && cash_tendered_centimes > 0;
    if !applicable {
        return 0;
    }
    // ceil(base * 0.01 / 100) * 100, all-integer: ((base + 9999) / 10000) * 100.
    let stepped = (base_for_timbre_centimes.saturating_add(9_999) / 10_000).saturating_mul(100);
    stepped.clamp(TIMBRE_MIN_CENTIMES, TIMBRE_MAX_CENTIMES)
}
