# ADR-068 - Tax regime IFU: no VAT in v1
Status: ACCEPTED (SESSION-ARC-001); validation gate OPEN
Context: The owner stated in chat that the shop operates under the IFU flat-tax regime (Impot Forfaitaire Unique). AUD-003 finding C8: production sale lines are priced with VAT rate 0 hardcoded (crates/application/src/use_cases/sales.rs, near L94-104 and L674); tax_rules is never read by production code. MASTER-ARCHITECTURE-v1.0.0 section 24 assumed VAT 19/9/0.
Decision: Version 1 computes, shows and prints no VAT. A document has a single total labelled "Total"; line prices are final prices. A settings key tax.regime is to be introduced by a BRK task with values IFU (default for this installation) and TVA (reserved, no UI in v1). The tax_rules schema and VAT code paths are deferred, not deleted; activating VAT requires a new ADR. In IFU mode the UI shows no VAT, HT or TTC labels. Timbre (stamp duty) behaviour stays as implemented (crates/domain/src/sales/pricing.rs:150-169) and is shown as its own line when applicable, pending professional validation.
Consequences: Existing zero VAT behaviour becomes explicit and correct for this shop instead of an accidental limitation.
Validation gate (OPEN): the owner's accountant must confirm (a) IFU status, (b) mandatory mentions on invoices under IFU, (c) timbre applicability, (d) wording for professional customers. No compliance claim is made by this project.
