# ADR-086: Release Candidate v1.0.0 Packaging and Production Approval

Status: ACCEPTED
Date: 2026-10-11
Session: SESSION-ARC-011 (REL-044)

## Context

All 10 constitutional modules (Caisse/Vente, Stock, Clients & Crédit,
Fournisseurs, Produits, Documents, Sessions Caisse, Rapports, Utilisateurs,
Paramètres) are built, routed, and tested. The workspace is green:
388 Rust workspace tests passing (49 suites, 0 failed, 4 ignored by design),
304 Vitest tests passing across 31 files, `cargo fmt`, `cargo clippy
-D warnings`, `npm run lint`, `npm run typecheck`, and `npm run build` all
clean (TASK-AUD-033 baseline, re-verified in REL-042/043/044).

Release engineering is complete: a fresh NSIS installer was built with
`npx tauri build` (exit 0) — `Baraka UltraPOS_1.0.0_x64-setup.exe`,
221 552 107 bytes (~211 MiB, offline WebView2 bundled, no internet required
on the shop machine), SHA-256
`C608C32A8C96B089CB51E187DE473AD0FCCD3E728E8B1C07D0311C1E65D75934`,
replacing the pre-redesign 2026-09-30 bundle. Release benchmarks were
measured on the release profile (M1 product_search p50 0.235 ms,
M2 atomic_sale p50 3.561 ms, M3 print_job_insert p50 1.025 ms; same order
of magnitude as the historical run). Viewport invariants (ADR-066:
1280×640 default, 1024×600 minimum, no page-level scrollbars) and data
preservation (`%APPDATA%\com.baraka.ultrapos\baraka.db` untouched by
install/reinstall/uninstall; no destructive NSIS hooks) were audited and
recorded in the §38 manifest (`docs/operations/PRODUCTION-READINESS-AUDIT-v1.0.0.md`).
The release-drill version pin (open item F2) was aligned to migration 14 and
verified green read-only against a scratch database.

## Decision

1. The v1.0.0 NSIS bundle in `target/release/bundle/nsis/` is approved as
   the production baseline and designated the canonical installer.
2. The bilingual Arabic/French UI (full RTL) and the locally bundled offline
   typography (Cairo, Inter, JetBrains Mono) are ratified as the shipped
   experience — no runtime font or content downloads.
3. Hardware thermal-printer testing (signature row in
   `thermal-printer-drill.md` §6) and the accountant tax questionnaire remain
   open as owner-facing operational gates; they do not block the build.
   Database at-rest encryption stays an accepted deviation (out of v1 scope).

## Reasons

- Every verifiable readiness criterion in CHARTER-v2.0 Section 9.2 is met
  with pasted evidence (gates, benchmarks, artifact hash, preservation and
  viewport audits); nothing is claimed beyond measured values.
- The residual open items are operational (shop-floor printer proof,
  accountant questionnaire), not engineering: no code change can close them.
- Freezing v1.0.0 on a hashed, dated artifact gives the shop a reproducible
  install story (release notes + handover guide) and gives future work a
  stable baseline to diff against.

## Consequences

- The codebase is feature-frozen for v1.0.0: no new dependencies, no schema
  changes (migrations 0001–0014 frozen), no domain-financial-logic changes
  without a new task and a new version number.
- The canonical installer path is
  `target/release/bundle/nsis/Baraka UltraPOS_1.0.0_x64-setup.exe`;
  any rebuild must reproduce its size class (~211 MiB) and be re-hashed into
  the operations docs.
- Post-release defects go through the standard regression law (failing test
  first) against this baseline.
